# アーキテクチャ

> これは「目指す姿」。今どこまでできているかは [status.md](status.md) を参照。

## 全体像

```
配信者の PC（外部への通信なし）

 マイク ─▶ audio ─┬─ 音量 ──▶ detect ──── SpeechStarted / SpeechEnded ─┐
                  └─ 音声のブロック（最大 1 秒分）▶ keywords ─ Keyword ─┤
 ホットキー ─▶ hotkey ─────────────────────────────────── Hotkey ──────┤
 時計 ───────────────────────────────────────────────── Tick ────────┤
                                                                      ▼
                                       app：入力のキュー（asyncio.Queue、1 つ）
                                                                      │ 取り出すのは 1 つのタスクだけ
                                                                      ▼
                                            state（Brain：テンション・沈黙・イベント・出口）
                                                                      │ Mouth / TensionChanged / Say / Effect
                                                                      ▼
                                            lines（Say のセリフ選び）→ protocol のメッセージ
                                                                      │
                                                                      ▼
                                            server（WebSocket）──▶ OBS ブラウザソース（overlay ページ）

 config・lines の TOML は起動時に読んで検証する。log（配信ログ）は Phase 3
```

- スレッド（マイクのコールバック、認識用のスレッド、ホットキーのスレッド）からは `call_soon_threadsafe` でキューに入れる
- `TensionPeak` は今は送らずに捨てる（Phase 3 の配信ログで使う）

Python バックエンドがすべての判断を行い、OBS のページは「言われたとおりに表示する」だけにする。
両者をつなぐのは PC 内に閉じた WebSocket 1本で、ここが守るべき境界になる。

## モジュールと責務

予定するディレクトリ構成（`src/stream_buddy/` 配下）。

| --- | --- | --- | --- |

| `hotkey` | `RegisterHotKey` で決めたキーだけを受け取る | ホットキーイベント | FR-08, SR-05 |

| `app` | 入力のキューと `state` の `Brain` をつなぎ、出力をページへのメッセージにする。起動後のマイク・認識・時計を動かし、逆順で止める | `ws-protocol.md` のメッセージ | FR-02, FR-04〜FR-08 |
| `demo` | `--demo` の偽の入力の流れ | 入力 | FR-03 |

### `state` の中身

状態遷移の仕様は [state-machine.md](state-machine.md)。どのファイルも音声・ネットワーク・実時間を扱わず、時刻はミリ秒の引数で受け取る。

| ファイル | 中身 |
| --- | --- |
| `state/events.py` | 入力（`SpeechStarted`・`SpeechEnded`・`Keyword`・`Hotkey`・`Tick`）と出力（`Mouth`・`TensionChanged`・`Say`・`Effect`・`TensionPeak`）の型 |
| `state/constants.py` | state-machine.md の数値（窓、しきい値、待ち時間、吹き出しの最短間隔など） |
| `state/tension.py` | テンションの状態機械。遷移は [docs/state-machine.md](state-machine.md) を参照 |
| `state/silence.py` | 沈黙ハンター。遷移は [docs/state-machine.md](state-machine.md) を参照 |
| `state/event_fsm.py` | イベントの状態機械。遷移は [docs/state-machine.md](state-machine.md) を参照。演出中の扱いとキーワードの待ち時間（種類ごと）は [docs/state-machine.md](state-machine.md) を参照 |
| `state/arbiter.py` | 出口：`Say` の優先順位と最短間隔 |
| `state/brain.py` | 4 つをまとめる `Brain`。入力を各状態機械に配り、出力を出口に通して返す。状態機械どうしをつなぐのはここだけ |

## 依存の向き

- `state` は入力（`detect`・`keywords`・`hotkey`・時計）からイベントを受け取り、出力を返す。
  入力を集めて `state` に通し、出力をページへのメッセージにするのは `app`
- `state` は音声やネットワークを直接扱わない（テストしやすくするため）
- `overlay` はバックエンドに指示を送らない。接続時の `hello` 以外は受信専用

## 起動の流れ

`__main__.py` が 1〜7 を、`app.Runtime` がサーバーの起動後に 8・9 を行う。
失敗したら、それまでに始めたものを片付けてから終わる。

1. `config` を読み込み、検証する
2. セリフ集（`lines`）を読み込み、検証する
3. 保存済みのトークンを読み込む。初回、形が違うとき、`--reset-token` のときは作り直して保存する（ADR 0002）
4. `keywords.enabled` なら、音声認識モデルをハッシュで確かめて読み込む。**ほかのスレッドが動き出す前に行う**（下の「既知の制約と回避策」）。モデルがなければキーワード検知なしで続ける
5. ホットキーを登録する（専用のスレッド）。1 つも登録できなくても起動は続ける（警告を出す）
6. マイクを選び、ストリームを用意する。見つからなければ起動しない（5 のホットキーの登録を外してから終わる）。
   ここではまだ音を取らない（取り始めるのは 8）
   - マイクを早めに用意するのは、OBS 用の URL を表示する前に、マイクが見つからないことを知らせるため。
     URL が出たあとで終わると、起動できたように見えてしまう
7. `server` が `127.0.0.1` で待ち受けを始め、OBS 用の URL（トークン入り）をコンソールに表示する
8. マイクの音を取り始め、認識用のスレッドを始める
9. 時計（`Tick`。間隔は [docs/state-machine.md](state-machine.md) を参照）と、キューを処理するタスクを始める

終了（Ctrl+C を含む）は逆の順番で行う。どこかで例外が起きても、マイクを閉じる・ホットキーの登録を外す・スレッドを止める、は必ず行う。

- `--demo`：マイク・音声認識・ホットキーは使わず、`demo.py` の流れ（偽の入力）を `state` に入れる。状態機械とセリフ選びは本物が動く
- コンソールに出すのは、OBS の URL、起動・終了のお知らせ、警告だけ。発話の内容やセリフ選びの途中経過は出さない

## 既知の制約と回避策

### Vosk が日本語を含むパスを扱えない

- **制約**：Vosk（`libvosk.dll`）は、日本語などの ASCII 以外の文字を含むパスにあるモデルを読み込めない。
  ユーザー名が日本語の PC で、exe をデスクトップなどに置くと、既定のモデルの場所（exe の隣の `models/`）がこれに当たる
- **回避策**：モデルを読み込む間だけ、カレントフォルダをモデルのフォルダに移し、Vosk には相対パス `.` を渡す。
  読み込みが終わったら（失敗して例外が起きたときも）、必ず元のカレントフォルダに戻す（`keywords.VoskModel`）
- **ほかのスレッドが動き出す前にだけ行う理由**：カレントフォルダはプロセス全体で1つで、スレッドごとではない。
  ほかのスレッド（マイクのコールバック、サーバー、認識用のスレッド）が動いている間に変えると、
  そのスレッドが相対パスで開くファイルの場所が一時的に変わってしまう。
  そのため、モデルの読み込みは起動時、マイクを開く前・サーバーを起動する前に行う
- Vosk のエラーログは `SetLogLevel(-1)` でも止まらずにコンソールに出るが、相対パスで渡しているため、フォルダのパスは出ない
