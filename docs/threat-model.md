# 脅威モデル

## 前提

stream-buddy は配信者の PC の中だけで動き、外部に公開するサーバーを持たない。
そのため、守るべき入り口は次の3つに絞られる。

1. **PC 内で動くローカルサーバー**（WebSocket とページ配信）
2. **公開リポジトリと配布物**（コード、exe、依存ライブラリ）
3. **ユーザーの PC 上のファイル**（設定、ログ、音声認識モデル）

## 守るもの

| 資産 | 漏れる・壊れると何が起きるか |
| --- | --- |
| 配信者の音声・発話内容 | プライバシーの侵害 |
| 配信画面の表示内容 | 配信中に不適切な内容を表示させられる |
| PC 上のファイル | 意図しない場所への書き込み |
| 作者の個人情報・秘密情報 | 公開リポジトリからの流出 |
| 配布物の信頼性 | 改ざんされた exe を使わされる |

## 信頼の境界

```
[ インターネット ]  ×  外部への通信なし
        │
[ ブラウザで開いた任意のサイト ] ── ローカルの WebSocket に接続を試みる可能性（境界 A）
        │
[ 127.0.0.1 の stream-buddy サーバー ]
        │
[ OBS のブラウザソース（正規のページ） ]
```

境界 A が最も重要。ブラウザは、どのサイトからでも `ws://127.0.0.1:...` への接続を試みることができる。

## 脅威と対策

| ID | 脅威 | 対策 | 残るリスク |
| --- | --- | --- | --- |
| SR-01 | LAN の他機器からの接続 | `127.0.0.1` のみで待ち受け | なし |
| SR-02 | 悪意あるサイトからの WebSocket 接続 | Origin 確認＋起動ごとのトークン | トークン入りの URL が配信画面に映ると漏れる → README で注意喚起。トークンは起動ごとに変わる |
| SR-03 | 想定外のメッセージ | スキーマ検証して破棄 | なし |
| SR-04 | 表示文字によるスクリプト実行 | `textContent`、CSP | なし |
| SR-05 | キーロガー化・その疑い | `RegisterHotKey` のみ | なし |
| SR-06 | ログ出力先の悪用 | 出力先フォルダ内に限定、パス正規化 | なし |
| SR-07 | モデルファイルの改ざん | 公式配布元、ハッシュ確認 | 配布元自体の侵害 |
| SR-08 | 依存の脆弱性 | ロック、Dependabot、pip-audit | 未公表の脆弱性 |
| SR-09 | 秘密情報の流出 | 秘密情報を持たない設計、gitleaks、プッシュ保護 | なし |
| SR-10 | CI の悪用 | ハッシュ固定、最小権限 | なし |
| SR-11 | exe の改ざん・偽物 | CI ビルド、attestation、SHA-256 | 利用者が確認しない場合 → README で手順を案内 |

## AI 開発に関する対策

実装の多くを AI エージェントが行うため、次の多重の守りを置く。

1. **コミット時**：pre-commit（gitleaks、秘密鍵検知、ruff）
2. **AI の権限**：`.claude/settings.json` で push・フック回避・守りの設定ファイルの編集を禁止
3. **push は人間**：差分を確認してから push する
4. **GitHub 側**：プッシュ保護、ブランチ保護、CI が通らないとマージできない
