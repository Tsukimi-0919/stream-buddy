# 要件定義

stream-buddy v1 の要件。ID はタスク・テスト・コミットメッセージで共通に使う。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| 音声認識 | ローカルで完結させる（外部へ送らない） |
| メンダコのセリフ | 用意したセリフ集から選ぶ（AI 生成は将来の拡張） |
| 対象 OS | Windows 10 / 11 のみ |
| 配布形式 | exe（GitHub Releases）。PyInstaller で GitHub Actions 上でビルド。必要なら Nuitka に切り替え |
| コード署名 | 行わない。README で警告の理由とハッシュでの確認方法を説明する |
| パッケージ管理 | uv（`uv.lock` でバージョンとハッシュを固定） |
| 設定ファイル | TOML |
| メンダコの画像 | オリジナル。最初は AI で生成した 2D 画像。差し替え可能にする |

## やらないこと（v1）

配信プラットフォームのコメント連携、AI によるセリフ生成、クラウド連携、Mac / Linux 対応、インストーラー配布。

## 機能要件（FR）

| ID | 機能 | 内容 | Phase |
| --- | --- | --- | --- |
| FR-01 | マイク入力 | 使用するマイクを設定で選ぶ。音声はメモリ上で処理し保存しない | 1 |
| FR-02 | 発話検知 | 声が出ている間、メンダコの口をパクパクさせる | 1 |
| FR-03 | オーバーレイ表示 | ローカルサーバーが配信するページを OBS ブラウザソースで表示。背景透過とクロマキーを切り替え可能 | 1 |
| FR-04 | テンション管理 | 発話の頻度と勢いから Calm / Normal / High の3段階を決め、動きとセリフを変える | 2 |
| FR-05 | 沈黙ハンター | 一定時間（初期値 20 秒、設定可）発話がないとリアクションを出す | 2 |
| FR-06 | セリフ選択 | 状態とイベントごとのセリフ集から選ぶ。直前と同じセリフは避ける | 2 |
| FR-07 | キーワード検知 | 「死んだ」「勝った」などの言葉を聞き取ってイベントを起こす。言葉は設定で変更可能 | 2 |
| FR-08 | ホットキー | 決めたキー（初期値 F9 / F10）でイベントを起こす | 2 |
| FR-09 | 演出 | 死亡（暗転風＋しょんぼり）とクリア（紙吹雪＋虹色）の画面演出 | 3 |
| FR-10 | 配信ログ | テンション MAX とイベントの時刻を Markdown で保存。出力先に Obsidian の Vault を指定できる | 3 |
| FR-11 | 設定ファイル | マイク・しきい値・キー・キーワード・出力先を1つの TOML で管理 | 1 |

## 非機能要件（NFR）

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 軽さ | ゲームと配信ソフトの動作に体感できる影響を与えない。CPU 使用率の上限は Phase 1 で計測して決める |
| NFR-02 | 反応速度 | 発話開始からパクパク開始まで違和感のない遅さに収める。キーワード検知は 1〜2 秒程度の遅れを許容する |
| NFR-03 | OBS 親和性 | 背景透過を標準とし、クロマキーにも切り替えられる。OBS に URL を1つ設定するだけで表示できる |
| NFR-04 | 差し替えやすさ | 画像・セリフ集・キーワードは、コードを触らずファイルの差し替えで変更できる |
| NFR-05 | 保守性 | 音声・状態管理・通信・表示をモジュールで分け、それぞれ単独でテストできる |
| NFR-06 | オフライン動作 | 音声認識モデルの初回取得を除き、ネットワークなしで全機能が動く |

## セキュリティ要件（SR）

| ID | 脅威 | 対策 |
| --- | --- | --- |
| SR-01 | 同じ LAN の他の機器からサーバーに接続される | `127.0.0.1` だけで待ち受ける |
| SR-02 | 悪意あるサイトがローカルの WebSocket に接続して画面を乗っ取る | ページをローカルサーバーから配信し、Origin を確認。起動ごとのランダムなトークンで認証する |
| SR-03 | 想定外のメッセージで誤作動する | `docs/ws-protocol.md` のスキーマで検証し、合わないものは捨てる |
| SR-04 | 吹き出しの文字に仕込まれたスクリプトが動く | `textContent` で表示。Content-Security-Policy を設定する |
| SR-05 | ホットキー機能がキーロガーとして悪用・誤解される | `RegisterHotKey` で決めたキーだけを登録する |
| SR-06 | ログの出力先指定で意図しない場所に書かれる | ログは設定した `output_dir` の中にだけ書く。書き込み先のパスを正規化し、`output_dir` の中に収まっていることを確認してから書く |
| SR-07 | 音声認識モデルが改ざんされる | 公式配布元から取得しハッシュ値を確認する。リポジトリに含めない |
| SR-08 | 依存ライブラリの脆弱性 | `uv.lock` で固定し、Dependabot と `pip-audit` で監視する |
| SR-09 | 秘密情報・個人情報がリポジトリに入る | API キーを使わない設計。gitleaks・プッシュ保護・noreply アドレス |
| SR-10 | GitHub Actions 経由の攻撃 | Actions をコミットハッシュで固定し、`GITHUB_TOKEN` の権限を最小にする |
| SR-11 | 配布した exe の改ざん・偽物 | GitHub Actions でビルドし、ビルド証明（artifact attestation）と SHA-256 を添える |

## プライバシー

- 音声はメモリ上で処理し、ファイルに書き出さない
- 配信ログは初期設定で「時刻・イベント種別・テンション」のみ。発話テキストの保存は設定で明示的にオンにしたときだけ
- テレメトリや利用統計は送らない
