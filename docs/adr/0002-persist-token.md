# ADR 0002：URL のトークンを保存して使い回す

- 状態：採用
- 日付：2026-10-25

## 背景

T-03 では、ページと WebSocket の認証に使うトークン（SR-02）を起動ごとに作り、どこにも保存しない設計にした。
しかし T-04 で、次の問題がわかった。

- stream-buddy を再起動するとトークンが変わり、OBS のページは古いトークンで再接続を試み続けて、つながらない
- 配信者は起動のたびに、OBS のブラウザソースの URL を設定し直す必要がある

これでは「起動しておけば OBS 側は放っておいてよい」という使い方ができない。

## 決定

- トークンは初回の起動で `secrets.token_urlsafe(32)` で作り、`%LOCALAPPDATA%\stream-buddy\token` に保存する。2回目以降はこれを読み込んで使い回す
  - `LOCALAPPDATA` がなければ、エラーで終了する
  - 保存した中身が想定の形（43 文字、`A-Z a-z 0-9 _ -` のみ）でなければ作り直す
  - 書き込みは一時ファイルに書いてから置き換え、途中で止まっても壊れたファイルを残さない
- `--reset-token` オプションで作り直せるようにする。作り直したときは「OBS の URL を設定し直してください」と表示する
- トークンはコンソールの URL 表示以外には出さない（ログ・エラーメッセージにも含めない）
- 実装は `src/stream_buddy/token_store.py`

## 結果

- 再起動しても URL が変わらず、ページは自動で再接続できる
- 代わりに、URL が漏れたとき（配信画面に映ったときなど）は、作り直すまで有効なままになる
  - 対策：起動時のコンソールと README で「URL や開発者ツールの画面を配信に映さない」「映ってしまったら `--reset-token` で作り直す」と案内する
  - トークンだけでは接続できない（Origin・Host の確認があるため、外部のサイトからは使えない）ので、漏れたときの影響は限られる
- 保存先は Windows のユーザーごとのフォルダなので、同じ PC の他のユーザーからは読めない（OS の権限に任せる）
- テストでは `LOCALAPPDATA` を一時フォルダに差し替え、実際の場所には書かない
