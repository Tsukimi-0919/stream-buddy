# ADR 0003：キーワード検知に使う音声認識エンジン

- 状態：採用
- 日付：2026-10-26

## 背景

キーワード検知（FR-07）のために、音声認識エンジンを1つ選ぶ必要がある。候補は次の2つ。

- **Vosk**（`vosk-model-small-ja-0.22`）：文法（grammar）でキーワードだけを候補にできる
- **faster-whisper**（`tiny`・`base`、CPU、int8）：書き起こした文にキーワードが含まれるかで判定する

満たすべき要件と方針

- NFR-01（軽さ）：ゲームと配信ソフトの動作に体感できる影響を与えない
- NFR-02（反応速度）：キーワード検知は 1〜2 秒程度の遅れを許容する
- NFR-06（オフライン動作）：モデルの初回取得を除き、ネットワークなしで動く
- SR-07（モデルの改ざん）：公式配布元から取得し、ハッシュ値を確認する。リポジトリに含めない
- プライバシー：音声は保存しない。外部に送らない

## 比較の方法

- 道具：`spikes/asr_compare.py`（手順は `spikes/README.md`）
- 同じ発話（最大 3 秒）を全エンジンにかける。音声は保存しない
- 読み上げる言葉（各 3 回）
  - キーワード：「死んだ」「やられた」「勝った」「クリア」
  - キーワードではない言葉：「しんどい」「かったるい」「クリーム」「今日はいい天気」
  - 2回目の測定から、キーワードではない言葉に「買った」「よかった」「わかった」「なんだ」を加えた（「勝った」「死んだ」と同じ音・近い音での誤検知を測るため）
  - 3回目の測定では言葉を入れ替えた（「3回目の測定」を参照）
- 測定した環境：（CPU、メモリ、マイク、部屋の状況を記入）

## 比較の観点

| 観点 | 見るもの | 重み |
| --- | --- | --- |
| 正解率 | キーワードを正しく検知し、キーワードでない言葉で検知しなかった割合 | 高 |
| 誤検知 | キーワードでない言葉で検知した、または違うキーワードとして検知した回数（配信中の誤爆になる） | 高 |
| 反応速度 | 処理時間の平均と最大（NFR-02：1〜2 秒以内か） | 高 |
| 軽さ | 処理中の CPU 時間（NFR-01） | 中 |
| モデルの扱い | モデルのサイズ、取得方法、配布元、ハッシュの確認のしやすさ（SR-07） | 中 |
| 言葉の変更 | 設定でキーワードを変えたときに対応できるか（FR-07、NFR-04） | 中 |
| 起動時間 | モデルの読み込み時間 | 低 |

### 1回目の測定

読み上げる言葉は「比較の方法」の 8 語を各 3 回（合計 24 回）。Vosk の文法には、キーワードをそのまま（「死んだ」「勝った」など）指定した。

補足

- vosk の「死んだ」「勝った」の NG 6 回は、文法に語彙にない語を指定したため、候補に入っていなかったことが原因
- vosk の誤検知 3 回は、すべて「クリーム」を「クリア」と認識したもの
- whisper は「死んだ」「勝った」を「新鮮だ」「買った」「カッター」など、同音・近い音の別の語に書き起こした
- whisper-base は処理時間の最大が 3122 ms で、NFR-02（1〜2 秒）を超える。whisper-tiny も 1 回の発話で平均 1123 ms の CPU 時間を使う（NFR-01）

この結果から Vosk を第一候補にした。課題は次の2つ。

1. 「死んだ」「勝った」が Vosk の語彙にない（1 語としては登録されていない）
2. 「クリーム」が「クリア」として誤検知される

#### Vosk の語彙の調査（`graph/words.txt`）

- 「死んだ」「勝った」は 1 語としては登録されていない。ひらがな・カタカナの「しんだ」「シンダ」もない
- 語彙にあるもの
  - 「死」を含む語：「死」「死ん」「死んで」「死んじゃ」「死に」「死ぬ」「死ね」など（ほかに「必死」「即死」などの熟語）
  - 「勝」を含む語：「勝」「勝っ」「勝って」「勝つ」「勝ち」「勝た」「勝て」など（ほかに「優勝」「楽勝」などの熟語）
  - かな：「しん」「シン」「だ」「ダ」「た」「かっ」「カッ」「かった」「カッタ」
  - おとりにする言葉：「クリーム」「しんどい」「かったるい」「買った」「よかった」はどれも 1 語で登録されている
- 文法は空白でつないだ句も指定できるため、「死ん だ」「勝っ た」と語彙にある単語の組み合わせで表す

#### 比較スクリプトの変更（2回目の測定に向けて）

- Vosk の文法を「死ん だ」「勝っ た」の句にした
- Vosk の文法に、キーワードではない「おとりの言葉」（クリーム、しんどい、かったるい、買った、よかった）を入れた。
  おとりとして認識されたら「検知なし」と判定する
- 読み上げる「キーワードではない言葉」に「買った」「よかった」「わかった」「なんだ」を加えた（各 3 回、合計 36 回）
- 「わかった」「なんだ」は、わざとおとりの言葉に入れていない
  - おとりの言葉は、文法に入れた言葉の誤検知しか防げない。配信中には、文法に入れていない似た音の言葉（「わかった」は「勝った」、「なんだ」は「死んだ」に近い）も話す
  - その言葉がキーワードに寄せられて誤検知されるかを測り、おとりの言葉だけで足りるか（確からしさでの足切りなどが要るか）を判断する材料にする

### 気づいたこと

- マイクを使わない動作確認（無音とノイズ）での観察（T-06 の作業時）
  - whisper-tiny は、ノイズから「ご視聴ありがとうございました」という存在しない文を作った（キーワードは含まないので誤検知にはならなかった）
  - Whisper は無音や無音に近い音で、書き起こしをやり直すため数秒かかることがあった（tiny で最大 6 秒程度）
- 測定での観察
  - 近い音のおとりの言葉が、キーワードではない言葉を吸い込んで誤検知を防いだことがある
    （2回目：「わかった」を「よかった」、3回目：「買った」を「かったるい」と認識した。どちらも判定は検知なし）

## 決定

- エンジンは Vosk（`vosk-model-small-ja-0.22`）を採用する
- 既定のキーワード
  - 死亡：「死んだ」「やられた」
  - クリア：「クリア」「やったー」
- 「勝った」は「買った」と同じ音、「ナイス」は「ないです」とほぼ同じ音のため、既定から外す
- 既定のおとりの言葉：「やっぱり」「クリーム」「しんどい」「かったるい」
  - 「やっぱり」のおとりの効果は、キーワード検知を本体に組み込むタスクの手動確認で確かめる
- 同じ音の言葉は、おとりの言葉でも防げない。確実に演出を出したいときはホットキーを使う

Whisper（faster-whisper）を採用しない理由

- 処理時間：whisper-base は最大 3122 ms で、NFR-02（1〜2 秒）を超える
- CPU 時間：1 回の発話で、whisper-tiny は平均 1123 ms、whisper-base は平均 3876 ms 使う（NFR-01）
- 同音の書き起こし：「死んだ」「勝った」を「新鮮だ」「買った」「カッター」など、同音・近い音の別の語に書き起こした
- 無音からの文の生成：whisper-tiny は、マイクを使わない動作確認でノイズから「ご視聴ありがとうございました」という存在しない文を作った。
  キーワードを含む文を作れば誤検知になる

## 結果
