# ADR 0001：判断を ADR として記録する

- 状態：採用
- 日付：2026-10-25

## 背景

AI エージェントが実装の多くを担うため、「なぜそう決めたか」がコードから読み取れないと、
後のタスクで同じ議論を繰り返したり、決定を知らずに覆したりする恐れがある。

## 決定

技術選定や設計の判断は、`docs/adr/NNNN-<内容>.md` に1件1ファイルで記録する。
形式は「状態・日付・背景・決定・結果」の5項目とする。

## 結果

- AI へのタスク指示で、関連する ADR を参照させられる
- Zenn 記事を書くときの材料になる
- 決定を変えるときは、新しい ADR を書いて古いものを「置き換え済み」にする
