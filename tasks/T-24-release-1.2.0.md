## 目的

## v1.1.0 からの変更（人が確認した結果）

- テンションの反応を速くした（窓 30 秒 → 15 秒、変化のあとに変えない時間 5 秒 → 3 秒）
- `config.toml` の `[tension]` で `window_seconds`（5〜30）と `hold_seconds`（1〜10）を変えられる
- 「話した割合」を数えるときだけ、1.0 秒未満の間（息継ぎ・文の切れ目）を話していたとみなす。口パクは変えない
- 手動確認（2026-11-13）
  - 窓 10・15・20 秒を試し、15 秒を既定値のままにする（10 秒は少し黙るとすぐ Calm に戻る、20 秒は上がるのも戻るのもゆっくり）
  - ふつうに話したときの「話した割合」は 50 前後が上限だった。High には、話し続けたうえでクリアの加点が乗ったときに届く。しきい値（70）は変えず、配信で使ってから見直す

## CPU とメモリの計測（NFR-01、人が行った結果）

- 日付：2026-11-14
- 条件：GitHub Actions ではなく手元でビルドした onedir の exe（T-23 のマージ後の `main`）。OBS Studio でメンダコのブラウザソースを表示し、話し続けながら F9・F10 も押した
- 結果：タスクマネージャーで `stream-buddy.exe` の CPU は **約 0.4%**、メモリは **約 220 MB**。話している間・3 分間の平均でも大きく変わらなかった
- メモリの大部分は音声認識モデル（約 100 MB）の読み込み分。使っている間に増えていく様子はなかった
- 判断：NFR-01（ゲームと配信ソフトの動作に体感できる影響を与えない）を満たしている
