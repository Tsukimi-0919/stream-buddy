# タスク：v1.0.1 の小さな修正（OBS を先に開いたとき・演出中のホットキー・モデルの置き場所）

- ID：T-21
- Phase：v1.0.1
- 関連要件：FR-07〜FR-09、NFR-03、イベントの状態機械（ST-21〜ST-26）
- ブランチ名：`fix/v1.0.1-small-fixes`

## 目的

v1.0.0 を使ってみて見つかった、次の3つを直す。

1. OBS を先に開いてから stream-buddy を起動すると、OBS にメンダコが出ない（画像も出ない）
2. しょんぼり（死亡）の演出中にクリアのホットキーを押しても、しょんぼりのまま
3. 音声認識モデルが見つからないとき、どこに置けばよいかがわかりにくい

## 原因（調べた結果）

### 1. OBS を先に開いたとき

- ページ（HTML・CSS・JS・画像）も WebSocket も、stream-buddy のサーバーが配っている
- OBS を先に開くと、ブラウザソースは**ページの読み込みそのもの**に失敗する。再接続の処理（`app.js` の `scheduleReconnect`）はページの中にあるため、動かない
- stream-buddy を先に起動したときは問題なく表示される（人が確認した）
- ブラウザソースを右クリック →「更新」を押すと、ページを読み込み直せる

根本的な対策（ページを OBS のローカルファイルにする、など）は、Origin・トークン・CSP の設計に関わるため、**このタスクではやらない**。案を ADR の下書きとして報告するだけにする（下の「4」）。

### 2. 演出中のホットキー

- 仕様どおりの動き。ST-25 で、演出中（Effecting）は**ホットキーも含めて**無視している
- ページ側（`showEffect`）は、演出中に次の演出が来ても最初から出し直せる作りになっている

### 3. モデルの置き場所

- モデルがないとき、`keywords.MISSING_MODEL_MESSAGE` を表示するが、**どのフォルダを探したか**が出ない
- v1.0.0 の試用で、exe と同じフォルダに置いたつもりでも、フォルダが1段深い・浅いなどで見つからないことがあった

## 仕様

### 1. OBS を先に開いたときの案内

- 起動時の URL の案内（`_print_url`）のあとに、次の趣旨の1行を足す
  - 「OBS を先に開いていた場合は、ブラウザソースを右クリックして『更新』を押してください」
- README の「6. OBS の設定」に、同じことを書く
  - stream-buddy を先に起動するのがおすすめであること
  - OBS を先に開いていて、メンダコが出ないときは、ブラウザソースの「更新」を押すこと
- README に「困ったとき」の節がなければ作り、この項目と、下の 3 の項目を入れる（見出しは短く）

### 2. 演出中のホットキーで、違う種類の演出に切り替える（ST-25 の変更）

- 演出中（Effecting(k)）に、**違う種類**のホットキー `Hotkey(j)`（j ≠ k）が来たら、すぐに Effecting(j) に移り、`Effect(j)`・`Say(j)` を出す（新しい遷移 ST-27）
  - 演出の開始時刻は、新しい演出の開始時刻にする（3 秒は j の開始から数える）
  - j の「前回の演出開始の時刻」も更新する
- 演出中の**同じ種類**のホットキーは、今までどおり無視する（演出を出し直さない）
- 演出中の**キーワード**は、種類に関係なく今までどおり無視する（聞き間違いで演出が入れ替わらないように）
- 吹き出し：`death` と `clear` は Arbiter で必ず出すもの（`ALWAYS`）なので、切り替えたときも新しいセリフが出ること
- `docs/state-machine.md` の「3. イベント」を直す
  - 図に `Effecting --> Effecting: ST-27 違う種類の Hotkey` を加え、ST-25 を「キーワードと、同じ種類の Hotkey は無視」に直す
  - 表に ST-27 を加え、ST-25 の条件を直す
  - 箇条書きの「演出中（Effecting）は、ホットキーも含めて無視する」を、新しい決まりに直す
  - 決定の表に「演出中の違う種類のホットキー：受け付けて切り替える（2026-11-13 に変更）」を加える

### 3. モデルが見つからないときに、探した場所を表示する

- モデルが見つからないとき（起動時と `--check-model` の両方）、メッセージに**探したフォルダの絶対パス**を添える
  - 例：「音声認識モデルが見つかりません。探した場所：<パス>」
  - パスは**コンソールに表示するだけ**。ログ（ストリームログなど）やファイルには書かない
- よくある置き間違い（`models\vosk-model-small-ja-0.22\vosk-model-small-ja-0.22\am` のような二重のフォルダ）を見つけたら、「1段深く展開されているようです」と案内する
  - 調べるのは、探したフォルダの**1段下**に同じ名前のフォルダがあるかだけ。それ以上は探さない
- README の「音声認識モデルの取得」に、正しい置き方のフォルダの図を加える

  ```text
  stream-buddy\
  ├─ stream-buddy.exe
  ├─ _internal\
  └─ models\
     └─ vosk-model-small-ja-0.22\
        ├─ am\
        ├─ conf\
        ├─ graph\
        └─ ...
  ```

  （実際のフォルダの名前は、モデルの zip の中身と見比べて正しいものにする）

### 4. OBS を先に開いたときの根本的な対策（報告のみ）

- コードは変えず、案を報告に書く（人が ADR にするか決める）
- 例：ページを OBS のローカルファイルにする、OBS の設定で直せるか、など。それぞれ、Origin の確認・トークン・CSP にどう響くかを短く書く
